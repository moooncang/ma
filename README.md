## 먼저 읽을 것 — 누가 무엇을 맡는가

- 문구를 고칠 일이 생기면 `_build/data.py`만 고친다. 문구 담당은 Claude다
- 구성은 전작 사이트를 따랐다: 「일레온」 https://moooncang.github.io/II/ , 「변경의 신임 영주가 되었다」 https://moooncang.github.io/ern/

## 입장 연출 콘셉트 (작가님 지정)

바탕 구조: **배경에는 처음부터 악보가 가득 깔려 있다. 그 위에 검은 그림자가 드리워져 있어서 보이지 않을 뿐이다.** 빛이 나는 것은 새로 그려지는 것이 아니라 그 그림자를 걷어 내는 것이고, 마지막에 날아가는 악보가 바로 이 깔려 있던 악보다.

1. **어둠** — 검은 화면. 은은하게 빛나며 일렁이는 음표 하나가 떠 있고, 그 둘레만 그림자가 옅게 걷혀 깔린 악보가 비친다
2. **누름** — 그 음표를 누르면 피아노 건반 한 음이 울린다. 중앙 빛과 흩어진 입자는 2.4초에 걸쳐 넓게 퍼지며 사라지고, 1.2초 뒤 다음 음표가 나타난다
3. **악기 넷이 하나씩** — 바이올린 → 피아노 → 첼로 → 플루트 순서로 한 악기씩 소리가 난다. 첫 클릭부터 합주까지 간격은 1.2 → 1.2 → 0.9 → 0.6 → 0.45초로 좁아져 리듬이 점점 빨라진다. 소리마다 화면의 서로 다른 곳에서 음표가 반짝이며 그 자리의 그림자를 걷어 내 악보를 비추고, **곧 꺼져 다시 어둠으로 돌아간다**
4. **합주** — 마지막 0.45초에는 그림자가 안으로 밀려들고 빛이 모인다. 이어서 네 악기가 앞선 단음보다 힘 있게 동시에 울리며 은은한 청색광의 빛 입자가 앞뒤·사방으로 퍼지고 중심에서 물결이 번진다. 물결이 지나가는 띠 안의 악보만 굴절된다. 커진 네 음표와 빛의 파동이 함께 펼쳐지면서 그림자가 전부 걷히고 화면이 **확** 밝아진다. 깔려 있던 악보가 한꺼번에 드러난다
5. **악보** — 그 악보들이 파라라락 날아간다
6. **입장** — 악보가 걷힌 자리에서 그대로 첫 화면으로 들어간다

입장 페이지는 2026-11-23에 새로 구현했다. 실제 클래식 곡을 조판한 악보 SVG 12쪽과 실시간 빛 입자로 이루어진 음표 4종을 사용한다. 큰 악보들이 크기·각도·방향을 달리하며 흩뿌려져 겹쳐 있고, 빛 궤적과 별 모양 입자가 음표 주변에서 반응한다. 소리는 VSCO 2 CE의 CC0 실제 악기 녹음으로, 첫 클릭 때 피아노 한 음, 이어서 바이올린·피아노·첼로·플루트가 각 음표의 등장에 맞춰 한 음씩 들리고 마지막에 네 악기가 함께 울린다. 피아노 아르페지오는 사용하지 않는다. 사용자 입력 뒤에만 재생하며 긴 감쇠·2.6초 홀 잔향·0.26/0.52초의 작은 스테레오 에코를 적용한다. 본문이 나타나도 마지막 잔향은 1.6초에 걸쳐 자연스럽게 사라진다.

종이는 WebGL 곡면으로 만들었다. 바람에 따른 굽힘·끝단의 비틀림·양면·종이결·그림자를 표현하며, 가만히 있을 때는 종이의 렌더 루프를 돌리지 않는다. 지원하는 브라우저에서는 Web Worker/OffscreenCanvas가 종이 질감·셰이더 준비·3D 렌더링을 맡아 화면 조작을 막지 않는다. 3D 첫 화면이 완전히 나타날 때까지 기존 악보를 유지해 교체 중 검은 깜빡임을 막는다. 같은 840×1188 해상도의 무손실 악보 캐시를 사용하고, 입자 630개와 종이 분할 수·그림자 2048 해상도는 유지한다. 처음에는 본문 이미지 디코딩을 미루고, 음표에 마우스를 올리거나 키보드 초점을 주거나 클릭하면 `home.html`의 실제 내용을 미리 뒤에 불러오기 때문에 악보가 날아가는 사이로 첫 화면이 바로 드러난다. 전환 뒤 주소를 `home.html`로 바꾸고 공용 동작을 연결한다. 본문은 같은 `home.html`을 사용하며 공용 스타일과 동작을 이어받는다.

WebGL을 쓸 수 없으면 같은 악보를 CSS로 날려 보낸다. 키보드 초점에서 나타나는 무음 입장 링크와 Escape 건너뛰기를 제공한다. 움직임 줄이기 설정에서는 연출과 소리 없이 입장한다. JavaScript가 꺼져 있어도 첫 화면 링크가 표시된다. 모든 입장 에셋과 Three.js는 저장소에서 읽는다. 출처·라이선스는 [입장 에셋 설명](assets/entry/README.md)을 참고한다.

### 세계

- 장소 36곳을 묶음 다섯(칸토레움 · 살롱 · 무대 · 루첼라 · 바깥)으로 나눠 놓고, 누르면 그곳의 배경 배너가 보인다. 좌우 화살표로도 넘긴다
- 아래에 루첼라, 칸토레움, 추첨석, 바깥을 글로 적었다

### 학사 (이 작품의 고유 체계)

- 살롱 넷: 미학, 수장, 소속 인물, 그리고 첫 화면과 같은 연주 반응 장치
- 무대와 얻는 길, 학사력
- 추첨 입학생을 보는 눈: 열두 사람이 여섯 대 여섯으로 갈린다. 이름을 누르면 그 사람이 어떻게 대하는지와 무엇에 풀리는지가 나온다
- 사건, 판정(평 견본 포함), 관계 단계, 정보창 견본(방문자가 시작 쪽에 적은 전공이 들어간다)

### 인물

- 고르는 화면: 한쪽에 명단, 다른 쪽에 카드와 소개. 묶음 셋(학생 · 교수 · 바깥)으로 거른다. `characters.html#b`처럼 주소로 바로 연다
- 상세: 첫등장 카드, 별명, 소개, 기록(나이 · 국적 · 전공 · 살롱 · 유저를 부르는 말 · 말투 · 대표곡 · 추첨 입학생에게 · 풀리면), 표정 열 장(평소 · 연주 · 기쁨 · 슬픔 · 눈물 · 당황 · 놀람 · 부끄러움 · 분노 · 무대)
- 표정은 좌우 화살표로, 앞뒤 인물은 Q와 E로 넘긴다

### 시작

- 모드 슬롯 세 장(♭ 추첨 입학 · ♯ 수석 입학 · ♮ 자유). 무엇을 쥐고 시작하는지와 난이도
- 유저노트 초안: 모드와 이름 · 전공 · 국적 · 실력과 경력을 적으면 붙여 넣을 글이 만들어지고 버튼으로 복사한다
- 플레이 안내와 성인 작품 표시

## 글 원칙

- 설정 문구는 전부 작품 문서(`docs/`의 메인 프롬과 키워드북)에서 옮겨 적는다. 사이트를 위해 설정을 지어내지 않는다
- 섹션 라벨은 담백한 영문, 한글은 제목과 본문
- 설명은 완결된 문장으로 쓴다. 과장하는 말, 분위기 문장, 감성 문구를 넣지 않는다
- 화면 문구에 줄표(— –)를 쓰지 않는다. 생성기가 만들 때 검사한다
- 줄거리를 쓰지 않는다. 정해진 엔딩이 없는 작품이다
- 작가님이 확인하지 않은 설정은 싣지 않는다. 인물 대사, 질투 표현, 동기 관계 같은 것이 빠진 이유다
- 모티브 음악가의 이름은 첫등장 카드의 별명(「베토벤의 재림」)으로만 나온다

## 만들고 고치는 법

```
python _build/build.py
```

- `_build/data.py` — 화면에 나오는 모든 문구와 데이터. 고칠 곳은 여기다
- `_build/build.py` — 쪽의 틀. 실행하면 저장소 최상단의 html 17개를 다시 쓰고 검사한다(줄표, 없는 그림과 쪽, 인물 구성)
- `assets/css/style.css` — 공통·첫 화면, `pages.css` — 내부 쪽, `motion.css` — 움직임, `fonts.css` — 자체 호스팅 글꼴. `assets/js/main.js`는 html의 `data-*` 표시를 보고 동작을 붙인다
- html을 손으로 고치지 않는다. `index.html`(입장)만 손으로 쓴 파일이고 생성기가 건드리지 않는다

### 본문 디자인·동작·검증 (2026-11-24)

- 첫 화면은 어두운 공연장, 커서를 올리면 펼쳐지는 인물 여섯 장, 밝은 소개 지면, 어두운 무대 선택, 살롱 반응, 드래그 인물 갤러리, 건반 형태 학사력으로 이어진다.
- 세계에는 파노라마 장소 탐색, 학사에는 살롱 프로그램과 반응 패널, 인물에는 고정 명단과 전체 카드, 시작에는 입학 모드와 노트 작성 패널을 적용했다.
- 스크롤 등장·제목 선의 확장·배경 시차·읽기 진행률·커서 조명·이미지 원근·이미지 전환·선택 반응을 제공한다. 스크롤과 포인터 계산은 하나의 이벤트 기반 프레임으로 합치며, 가만히 있을 때 반복 렌더링하지 않는다. 동작 줄이기 설정과 JavaScript 없는 환경에서도 본문을 볼 수 있다.
- 한글·영문 글꼴은 총 316KB의 WOFF2로 자체 제공한다. 외부 Google Fonts 연결이 필요 없다. 라이선스와 재생성 방법은 [글꼴 설명](assets/fonts/README.md)을 참고한다.
- `NODE_PATH=/tmp/ma-tools/node_modules node _build/test-site.cjs`로 17쪽의 원문·링크·접근성 문구 보존, PC·모바일 넘침, 선택·드래그·키보드·해시·입력·복사·전공 저장, 동작 줄이기와 JavaScript 없는 환경을 검사한다.
- 원문 기준은 `_build/site-content-baseline.json`에 저장했다. `SITE_TEST_GROUP=copy|pages|desktop|mobile|motion|nojs`로 검사 범위를 고를 수 있다. 정식 문구를 바꿀 때는 이 기준도 승인된 문구와 함께 갱신한다.

### 입장 페이지 개발·검증

- `index.html`, `assets/css/entry.css`, `assets/js/entry.js`가 입장 화면의 뼈대·모양·순서를 담당한다.
- `assets/js/entry-scene.js`는 worker 연결, `entry-paper-renderer.js`와 `entry-paper-worker.js`는 종이의 3D 움직임, `entry-particles.js`와 `entry-notes.js`는 빛 입자 음표, `entry-audio.js`는 녹음 샘플과 잔향을 담당한다.
- 로컬 실행: 저장소에서 `python -m http.server 4173 --bind 0.0.0.0`.
- 브라우저 검사 도구를 별도 경로에 설치한다: `npm install --prefix /tmp/ma-tools --cache /tmp/ma-npm-cache playwright@1.58.2`.
- `NODE_PATH=/tmp/ma-tools/node_modules node _build/test-entry.cjs`로 PC·모바일·키보드·동작 줄이기·WebGL/오디오 불가·건너뛰기·전환 후 본문 동작을 검사한다. Chromium 기본 경로는 `/usr/bin/chromium`; `CHROMIUM_PATH`, `ENTRY_TEST_URL`로 바꿀 수 있다.
- 악보 재생성: `python -m pip install --target /tmp/ma-score-tools verovio==6.4.1` 후 `PYTHONPATH=/tmp/ma-score-tools python _build/entry-scores.py`.
- 음원 재생성: Python 3와 ffmpeg가 있는 환경에서 `python _build/entry-audio.py`. 고정된 원본 커밋과 SHA-256을 검사하고 4개 녹음을 가공한다.
- 캐시 재생성: Playwright와 Python Pillow가 있는 환경에서 `NODE_PATH=/tmp/ma-tools/node_modules node _build/entry-assets.cjs`. 악보의 무손실 픽셀 일치를 검사하고 같은 630개 음표 좌표를 저장한다.
- 성능 비교: 다른 브라우저 검사를 동시에 실행하지 않고 `NODE_PATH=/tmp/ma-tools/node_modules node _build/profile-entry.cjs 이름`. `/tmp/ma-entry-profile`에 UI 스레드의 긴 작업·프레임 간격·CPU 프로필을 남긴다. GPU 종류에 따라 프레임 간격은 달라진다.
- 오디오 검사: `NODE_PATH=/tmp/ma-tools/node_modules node _build/test-entry-audio.cjs`. 실제 Web Audio 믹스를 렌더해 각 악기의 출력·클리핑·스테레오·끝 페이드를 확인한다. `ENTRY_AUDIO_REVIEW=/tmp/entrance.wav`를 지정하면 청취용 파일도 저장한다.

성능 비교 기록(2026-11-23): 같은 Linux / headless Chromium / SwiftShader에서 390×844, DPR 2로 측정했다. 초기 구간의 최대 프레임 간격은 1,833 ms → 67 ms, 초기 UI 스레드의 가장 긴 작업은 1,287 ms → 56 ms였다. 실제 기기 측정과는 구분한다. 악보 파일 합계는 SVG 3,169,333바이트 → 무손실 캐시 790,424바이트(75.1% 감소). 입자 수·렌더 해상도·종이 곡면·그림자는 유지했다.
